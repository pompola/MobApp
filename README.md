## Описание проекта

«Моя карта мест» — учебное мобильное приложение на React Native и Expo. Оно позволяет добавлять места на карту, открывать карточку выбранного места, давать название и прикреплять к нему фотографии. Данные о местах и фотографиях сохраняются в локальной базе данных SQLite.

## Реализованные возможности

- Отображение интерактивной карты на экране приложения.
- Начальная позиция карты — район Перми.
- Добавление метки долгим нажатием на карту на мобильном устройстве.
- Сохранение координат и названия места в SQLite.
- Отображение добавленных меток на карте красными маркерами.
- Автоматическое название нового места с возможностью изменить его на экране деталей.
- Удаление места с карты с подтверждением; вместе с местом удаляется список его фотографий.
- Переход на экран подробной информации при нажатии на метку.
- Отображение широты и долготы выбранного места.
- Выбор одного или нескольких изображений из галереи устройства.
- Сохранение URI изображений в SQLite и отображение фотографий в карточке места.
- Просмотр выбранных изображений в списке фотографий места.
- Удаление изображения с подтверждением действия.
- Отображение сообщения при ошибке загрузки карты.
- Типизация данных маркеров, изображений и параметров маршрута с помощью TypeScript.
- Навигация между экраном карты и экраном деталей с помощью Expo Router.
- Экран ожидания при инициализации базы и экран ошибки с возможностью повторить подключение.

## Используемые технологии

- React Native
- Expo
- TypeScript
- Expo Router — файловая навигация
- React Native WebView — отображение веб-карты внутри приложения
- Leaflet — интерактивная карта
- OpenStreetMap — картографические данные
- Expo Image Picker — выбор изображений из галереи
- expo-sqlite — локальная база данных SQLite.

## Требования для запуска

- Node.js LTS
- npm
- Expo Go на мобильном устройстве, совместимый с используемой версией Expo
- Подключение к интернету для загрузки библиотеки Leaflet и тайлов OpenStreetMap

## Установка и запуск

1. Скачайте или клонируйте репозиторий проекта.
2. Откройте терминал в корневой папке проекта — там, где находится `package.json`.
3. Установите зависимости:

   ```bash
   npm install
   ```

4. Запустите сервер разработки Expo:

   ```bash
   npx expo start
   ```

5. Откройте приложение Expo Go на телефоне и отсканируйте QR-код из терминала или страницы Expo Dev Tools. Компьютер и телефон обычно должны быть подключены к одной сети Wi-Fi.

6. Дождитесь загрузки приложения и проверьте карту, добавление меток и работу с фотографиями.

## Как пользоваться приложением

1. На главном экране отображается карта.
2. Нажмите и удерживайте нужную точку карты, чтобы добавить место.
3. Новая запись сохраняется в SQLite, после чего маркер появляется на карте.
4. Нажмите на маркер, чтобы открыть экран «Детали места».
5. Измените название и нажмите «Сохранить название».
6. Нажмите «+ Добавить изображение» и выберите одну или несколько фотографий.
7. Чтобы удалить фотографию, нажмите «Удалить» под ней и подтвердите действие.
8. Чтобы удалить место, нажмите «Удалить место с карты» и подтвердите действие. Вместе с местом удаляются связанные записи фотографий.
9. Вернитесь на карту. Список мест обновится.

## Схема базы данных

Файл базы называется `markers.db`. Он создаётся и открывается модулем `src/database/schema.ts` в локальном хранилище приложения.

### Таблица `markers`

| Поле | Тип | Назначение |
|---|---|---|
| `id` | INTEGER | Первичный ключ, генерируется автоматически |
| `latitude` | REAL | Широта места |
| `longitude` | REAL | Долгота места |
| `created_at` | DATETIME | Дата и время создания |
| `name` | TEXT | Название места |

`name` добавлено отдельной миграцией версии 2. Для новых записей приложение устанавливает название `Место <id>`.

### Таблица `marker_images`

| Поле | Тип | Назначение |
|---|---|---|
| `id` | INTEGER | Первичный ключ изображения |
| `marker_id` | INTEGER | ID места, к которому относится изображение |
| `uri` | TEXT | URI выбранного изображения |
| `created_at` | DATETIME | Дата и время добавления |

Связь таблиц — **один ко многим**: у одного места может быть несколько изображений. Поле `marker_images.marker_id` ссылается на `markers.id`. Внешний ключ создан с `ON DELETE CASCADE`; также удаление места в прикладном коде выполняется явно и в транзакции. Для `marker_id` создан индекс, ускоряющий выборку фотографий места.

Включение `PRAGMA foreign_keys = ON` необходимо, чтобы SQLite применяла ограничения внешнего ключа для текущего соединения.

**Важно:** в таблице сохраняется URI изображения, а не само изображение в виде двоичных данных. Приложение показывает фотографию по этому URI. Если исходный файл станет недоступен или система очистит его из временного хранилища, URI может перестать открываться.

## Архитектура и работа с данными

Код разделён на три уровня:

1. **Экранный уровень (`src/app`)** — отображает интерфейс, принимает действия пользователя и вызывает методы контекста.
2. **Контекст (`src/context/DatabaseContext.tsx`)** — предоставляет экранам единый доступ к базе, управляет её состоянием и обрабатывает ошибки соединения.
3. **Слой базы (`src/database`)** — открывает базу, обновляет её схему и выполняет SQL-запросы.

Экранные компоненты не содержат SQL-запросов напрямую.

### Основные операции

- Создание места: `INSERT INTO markers`.
- Переименование: `UPDATE markers`.
- Получение списка: `SELECT ... FROM markers`.
- Получение одного места: `SELECT ... WHERE id = ?`.
- Добавление изображений: `INSERT INTO marker_images`.
- Получение фотографий места: `SELECT ... WHERE marker_id = ?`.
- Удаление изображения: `DELETE FROM marker_images`.
- Удаление места: удаление связанных изображений и места внутри одной транзакции.

В запросах используются параметры (`?`), а не подстановка пользовательских строк в SQL. Это помогает избежать ошибок при обработке значений и SQL-инъекций.

### Транзакции

Транзакция объединяет несколько SQL-операций в одну логическую операцию. Если одна из операций завершается ошибкой, SQLite откатывает изменения этой транзакции.

Транзакции используются:
- при удалении места и связанных с ним изображений;
- при добавлении нескольких изображений;
- при применении каждой миграции схемы.

## Обработка ошибок

В `src/database/errors.ts` определён класс `DatabaseError` и категории ошибок:

- `INIT` — ошибка открытия или начальной настройки базы;
- `MIGRATION` — ошибка обновления схемы или несовместимая версия;
- `TRANSACTION` — ошибка операции, выполняемой в транзакции;
- `CONSTRAINT` — нарушение ограничения SQLite, например внешнего ключа;
- `CONNECTION` — соединение недоступно или закрыто;
- `VALIDATION` — некорректные входные данные;
- `NOT_FOUND` — запись не найдена;
- `UNKNOWN` — ошибка, которую не удалось отнести к известной категории.

Валидация проверяет диапазоны координат, непустой URI и название места длиной не более 60 символов.

При ошибке инициализации приложение показывает экран ошибки и кнопку «Повторить». Ошибки отдельных операций передаются вызывающему экрану, где пользователю показывается сообщение. В режиме разработки операции логируются в консоль с префиксом `[DB]`.

## Версии базы данных и миграции

Текущая версия схемы хранится в SQLite-параметре `PRAGMA user_version`.

- **Миграция 1** создаёт таблицы `markers` и `marker_images`, внешний ключ и индекс.
- **Миграция 2** добавляет в `markers` поле `name` и заполняет названия для ранее созданных мест.

При запуске приложение сравнивает текущую версию базы с последней версией миграций и применяет только недостающие миграции. Если база создана более новой версией приложения, инициализация прекращается с ошибкой `MIGRATION`.

При добавлении изменений схемы следует создавать новую миграцию в конце массива `migrations` и увеличивать номер версии. Уже применённые миграции не следует переписывать.

## Принятые решения при реализации

- Для карты выбран Leaflet, встроенный в приложение через WebView. Это позволяет обрабатывать события карты и отображать метки без отдельного экрана веб-приложения.
- В качестве картографического источника используется OpenStreetMap.
- Данные маркеров и связанные с ними изображения объединены в общем React-контексте `MarkersContext`, чтобы они были доступны на экране карты и на экране деталей.
- Для перехода к деталям используется файловая маршрутизация Expo Router. Идентификатор и координаты места передаются как параметры маршрута.
- Новым местам присваивается название по умолчанию; пользователь может изменить его на экране деталей.
- Маркеры Leaflet оформлены собственным SVG-значком красного цвета, поэтому цвет не зависит от стандартных изображений Leaflet.
- Для выбора фотографий используется Expo Image Picker. Перед открытием галереи приложение запрашивает разрешение.
- Основные структуры данных описаны интерфейсами TypeScript в `src/types.ts`.

## Известные ограничения

- Для загрузки Leaflet и тайлов OpenStreetMap требуется интернет-соединение.
- В SQLite сохраняется URI фотографии, а не копия файла. Доступность фотографии зависит от того, остаётся ли этот URI действительным.
- Основной сценарий следует проверять на Android-устройстве; поведение системного выбора изображений и разрешений может отличаться на разных платформах.
- В приложении нет отдельного поля подробного описания места.
